# ADR-003: 市场开源决策 —— 代码全开、密钥全闭

- 状态：**已接受**
- 日期：2026-08
- 关联：ADR-001（信任双档与签名链）

## 背景

官方插件市场相关代码是否放进开源仓库？"市场"实际由三块性质不同的部分组成，需要分开决策。

## 决策

| 组成部分 | 性质 | 决策 |
|---|---|---|
| **客户端**（拉取列表 / 下载 / 验证签名） | 安全核心，本就存在于每个用户安装中 | **开源** |
| **协议**（插件包格式 / manifest schema / 签名算法 / registry API 规范） | 生态公共语言，第三方开发者依此写插件 | **开源** |
| **服务端参考实现**（registry API / 上传与审核后台 / 签名流水线） | 可部署的基础设施；秘密在密钥而非代码 | **开源** |
| **签名私钥 / 发布凭据 / 审核权限** | 秘密，不是代码 | **永不进仓库**：HSM / 离线保管 / 轮换 / 吊销机制 |

## 理由

1. **信任模型本身就是"透明度"**：官方插件靠"签名 + 审核"获得特权，用户凭什么信？凭能审计三件事——客户端验证了什么、审核标准是什么、更新链路有没有后门。开源市场栈直接服务 ADR-001 的信任模型；闭源就是"相信我"，与本项目定位矛盾。
2. **自建插件仓库 = 最受欢迎的功能之一**：受众是自建党。开放 registry 协议 + 服务端参考实现，用户可配镜像源 / 私有源（解决国内访问慢），第三方可托管镜像，生态白送。
3. **成本低**：registry 本质是 CRUD + 鉴权 + 文件分发 + 签名工具，代码量不大；社区回报（bug 报告 / PR）大于维护负担。
4. **先例**：VS Code 市场服务端闭源但协议开放（故有 [Open VSX](https://open-vsx.org)）；npm 协议与客户端全开放；Home Assistant Add-on Store 基本全开。本项目取"客户端 + 协议 + 参考服务端全开"，比 VS Code 更激进——盘子小，激进得起，且这是差异化。

## 防仿冒（唯一要认真管理的风险）

- 面板默认固定**官方 registry URL + 官方公钥**；改源需醒目警告 + "非官方源"角标；
- 插件 ID 命名空间：`official:<id>` vs `thirdparty:<id>`；"官方"徽章 = 官方公钥签名验证通过才算数；
- 签名覆盖 manifest + 代码哈希（ADR-001），签名后篡改即失效——这同时是防仿冒机制。

## 未来付费插件的分叉点

当前身份不具备付费服务资质，**现阶段不做付费**（免费 / 打赏制）。未来若做付费：最多闭掉"支付 + 授权校验"那一小块（像 VS Code 闭掉自家市场服务端），协议、客户端、插件格式仍然全开——不影响生态与信任。

## 后果

- 市场代码从一开始就在 `market/` 目录开源演进；
- 密钥管理流程（HSM / 轮换 / 吊销）从第一天就设计，与代码同步；
- "官方源固定 + 公钥固定"是客户端的强制默认，不是可选项。
