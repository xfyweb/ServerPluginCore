# ADR-004: OS 底线与威胁模型 —— 非 root + 资源限制，仅此而已

- 状态：**已接受**
- 日期：2026-08
- 关联：ADR-001（零环境权力模型）、ADR-002（运行时）

## 背景

ADR-001 移走了"插件对 OS 的直接访问"后，残余风险收敛为单一来源：**插件运行时（QuickJS）自身的安全漏洞**。若运行时被攻破，爆炸半径 = 插件进程的 OS 用户能碰到的一切。

## 决策：只保留三条 OS 底线

1. **daemon（面板）自身与其内运行的插件一律非 root**（跑专用低权限用户，如 `spc`）。daemon 启动时检测到以 root 运行即**拒绝启动**（fail-closed）；运行时漏洞被利用时，后果从"整台服务器沦陷"缩到"一个普通用户"。**这是唯一的 OS 层投资，成本≈零（内核原生、无额外进程）**。
2. **资源限制走 systemd**（CPU / 内存 / 磁盘配额）。权限模型与接口审查都管不了资源耗尽，必须 OS 层兜底。
3. **运行时安全更新自动跟进** + 锁文件（`pnpm-lock.yaml` + `patchedDependencies` 固定，含本地补丁，见 docs/spike-01）压供应链。

**明确不做**：每插件独立 uid / 多用户矩阵 / 容器——在零环境权力模型下这些不再必要（ADR-001 推论 2）。

## 威胁模型

```
威胁源：恶意插件、被攻破的依赖、运行时漏洞
    │
    ├─► 插件只能调宿主 API ──► 接口审查 + 宿主侧权限强制（主防线）
    ├─► 运行时自身漏洞 ──────► 非 root 兜底爆炸半径（唯一 OS 防线）
    └─► 资源耗尽 ────────────► QuickJS 沙箱内存/CPU 限制 + systemd 进程级配额
```

## 证据：运行时权限模型的绕过史（为什么不能押注运行时）

| CVE / GHSA | 影响版本 | 问题 |
|---|---|---|
| CVE-2025-61785 | Deno < 2.5.3 | `Deno.FsFile.utime` 绕过 `--deny-write` |
| CVE-2025-61786 | Deno < 2.5.3 | `Deno.FsFile.stat` 绕过 `--deny-read` |
| CVE-2026-49983 | Deno < 2.8.1 | `process.loadEnvFile()` 绕过 env 权限检查 |
| CVE-2026-49401 | Deno < 2.7.14 | Unicode 规范化不一致绕过 deny 路径（macOS/APFS） |
| CVE-2026-49406 | Deno < 2.7.12 | BYONM 模块解析路径穿越，绕过 `--allow-read`（供应链放大） |
| GHSA-m4pq-fv2w-6hrw | — | ANSI 注入伪造交互式权限提示 |
| CVE-2022-39275 | Deno < 1.24 | npm 缓存符号链接攻击，装包时可任意写文件 |

模式：**响应快（均为 patch release 修复），但"权限模型内部存在绕过"是常态**。因此本模型不把安全押在任何运行时权限机制上。

## 诚实备注（QuickJS 的局限）

QuickJS 是**解释器（无 JIT）**——攻击面比 V8 小一个量级（无 JIT 类型混淆类漏洞），这是选它为主沙箱的原因（ADR-005）。但**它不是零漏洞**：

- 解释器本身有 CVE / fuzz 崩溃史（GC 断言、历史内存问题）；
- **绑定层同样有坑**：quickjs-emscripten asyncify 变体的释放顺序 bug（Issue #261）是现实案例——依赖层需要本地补丁 + 回归测试持续维护（docs/spike-01）；
- "零环境权力"靠**注入面**保证（沙箱里没有 require/process，注入什么就是什么），但**注入面 = 能力面**——宿主 API 的边界纪律不能松（D3：单一强制点）。

因此本模型的安全不押在"运行时不被攻破"上，而是押在 **市场签名与源管理（ADR-001 v3）+ 危险权限点逐点授予（`grant: explicit`，ADR-001 v4）+ 非 root + 接口审查**。若未来第三方插件泛滥、运行时漏洞频发，再评估加一层"插件专用 uid"作为增量（成本仍低）。

## 后果

- 部署文档必须写明"非 root 是安全前提"，安装脚本默认创建专用用户；
- systemd 单元模板内置资源配额；
- 运行时版本更新纳入核心的自动更新链路。
