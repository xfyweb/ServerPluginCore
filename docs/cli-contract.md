# 命令行契约（`spc` / `spcdev`）

> 本文只写**能被依赖的部分**：受众与前提、**退出码**、TTY 行为、输出通道。
> 命令清单与实现细节看 `docs/build-layer-design.md` §10.5，**这里不重复**。
> 两个命令为什么分开：受众、前提、发布节奏都不同（2026-09-25 用户拍板）。
> 退出码表 2026-09-26 定。

## 1. 两个命令，两份受众

| | `spc` | `spcdev` |
|---|---|---|
| 是什么 | **管理面**（`status` / `daemon` / `plugin` / `source` …） | **作者工具**（`keygen` / `new` / `check` / `permission list` / `build` / `pack` / `watch`） |
| 前提 | 多数动词要 **daemon 在跑** | **全程本地**，不需要 daemon |
| 版本 | 随核心运行时一起分发（P5 起） | **必须与本仓库同版本** |
| 入口 | `core/cli.ts`（`bin/spc`） | `core/cli-dev.ts`（`bin/spcdev`） |

**为什么不做成"一个命令下的子指令集"**：混在一个入口里迟早出现"工具说没问题、本体说不行"，
而那是本项目最难查的一类错（原文见 §10.5 那条注）。

## 2. 退出码（**契约：只增不改**）

| 码 | 含义 | 现状 |
|---|---|---|
| `0` | 成功 | ✅ 已在用 |
| `1` | 一般失败（运行时错 / IO 错 / 未分类） | ✅ 已在用 |
| `2` | **用法错误**：未知动词或选项、参数缺失、互斥旗标同时给 | ⏳ ⑦b 起 |
| `3` | **门禁失败**：`BUILD_*` 一族（依赖闭包解析不到、内建未登记、`.node`、产物欠条、声明与实解不一致、作者不匹配） | ⏳ ⑦b 起 |
| `4` | **需要交互但非 TTY**（例：`spcdev keygen` 缺作者 ID ⇒ `AUTHOR_ID_REQUIRED`） | ⏳ ⑦b 起 |

- **`2` 与 `3` 必须分开**：CI 要能区分"**我参数写错了**"和"**这个插件过不了闸**"——
  否则流水线一律红，人还得读日志才知道该改哪儿。
- **`4` 的存在理由**：非 TTY 下**不猜**（fail-closed）。脚本要跑就得显式给 `--author` 一类旗标。
- ⛔ **别和守护进程停机那张表混**：优雅停 `0` / 第二次信号 `130` / 停机超时兜底 `124` / 停机自身出错 `1`
  （见 `docs/management-channel.md` 的**停机契约**、`docs/plugin-lifecycle-design.md` 的退出码行）——
  那是**同一个进程的停机路径**，不是 CLI 的失败分类。
- **退出码不承载人可读文案**：文案照常打印，别往码里塞。

## 3. TTY 行为

**原则：非 TTY 不猜 —— 缺什么就报 `4`。**

| 场景 | TTY | 非 TTY |
|---|---|---|
| `spcdev keygen` 需要作者 ID | 问一次（`--author` 可跳过） | `AUTHOR_ID_REQUIRED` ⇒ `4` |

作者 ID 的来源顺序：`--author` > `.spcdev/config.json` 里已有的 > 交互询问（仅 TTY）——**没有 `--id`**。

## 4. 输出通道

- **结果 → stdout**（`console.log`）；**诊断与错误 → stderr**（`console.error`），行首带 `[spc]` / `[spcdev]` 前缀。
  ⇒ 脚本判"这次跑炸了没有"只看 **stderr 有没有内容**，不必解析文案。
- **错误经 `core/i18n` 的 `renderThrown()` 渲染，不吐原始堆栈**：契约错误给「码 + 参数 + 提示」，
  未知异常才退化到异常形状。
- **`--json`**：动词可以带（现状：`check` 与 `permission list`），此时**结果整体走 stdout**、人可读文案让位。

## 5. 语言（从哪来 / 怎么选）

**可用的 locale = 磁盘上真实存在的 `core/i18n/locales/*.json`**（启动时列一次目录）。
加一门语言 = 放一个 JSON 文件，**不用改代码**（现状：`zh-CN`、`en-US`）。

### 5.1 探测链（优先级从高到低）

| # | 来源 | 说明 |
|---|---|---|
| 1 | `SPC_LANG` | **我们的显式覆盖，永远最高**。非空即请求，不再被重新解释 |
| 2 | `LANGUAGE` | GNU：冒号分隔的优先级表，取**第一段**（这个变量的用途就是"消息语言"） |
| 3 | `LC_ALL` | POSIX 通用优先级：`LC_ALL` > 类别 > `LANG` |
| 4 | `LC_MESSAGES` | 同上 |
| 5 | `LANG` | 同上 |
| 6 | **平台探测** | **只在 Windows / macOS**：读 ICU 的默认 locale（Node 没有 `os.locale()`） |
| 7 | 默认 | `zh-CN` |

- **POSIX 上不探第 6 档**：那里的平台机制就是上面那几个环境变量，而实测（2026-09-26 / WSL node v22.22.1）
  ICU 只是把它们重读一遍 —— 唯一分歧点是 `LANG=C.UTF-8`，**那时 ICU 会擅自给出 `en-US`**。
  让一个随 ICU 版本/构建而变的兜底值决定显示什么，是我们要避免的隐藏不确定性。
- **Windows 相反**：实测设了 `LANG` 也**不影响** Intl（它反映 OS 设置）⇒ 只能靠探测。
  ⚠️ 诚实备注：Windows 上它给的是**区域格式**而非 UI 语言（用美国区域设置的中文用户会拿到 `en-US`）。

### 5.2 归一化与特例

| 输入 | 结果 |
|---|---|
| `en-US` / `en-us` / `en_US` / `en_US.UTF-8` | 切到 `en-US`（大小写、下划线、POSIX 的 `.codeset` 与 `@modifier` 都不敏感） |
| `en` | ⚠️ **不猜**（不当成 `en-US`）⇒ 回退 `zh-CN` **并在 stderr 出声** |
| `C` / `POSIX` / `C.UTF-8`（在 `LANG` 等档） | **平台没有表达语言偏好** ⇒ 跳过该档继续往下 ⇒ 最终落默认 `zh-CN`，**不是英文**，也不报警 |
| `SPC_LANG=C` | 与上面**不同**：我们的变量一旦显式设了就照实报"不可用"（不替用户重新解释） |
| 空串 / 全空白 | 视为"没设"，继续往下 |
| 任何不存在的标签 | 回退默认 + 一行警告，并列出**可用值** |

### 5.3 出声的规矩

- **两种来源两个码**：`SPC_LANG` 来的 ⇒ `err.LOCALE_UNAVAILABLE`；系统环境 / 平台来的 ⇒
  `err.LOCALE_PLATFORM_UNAVAILABLE`（后者文案里给出 `SPC_LANG` 这个固定/静音开关）。
- 为什么回退而不 fail-closed 拒绝启动：这不是安全判定（不涉及权限/来源），且"缺翻译也要有话可说"
  是 i18n 层既有的原则。**但静默不行** —— 静默回退正是当初"设了没用"的那个 bug。
- ⚠️ 这些值**只用于匹配，绝不拼进文件路径** —— 会被打开的只有目录里列出来的那些名字。
- 回归用例：`core/__tests__/i18n-locale.test.ts`（20 条，含三条走**子进程 + 环境变量**的端到端；
  所有用例都注入 env 并显式给平台信号 ⇒ 结果与跑测机器的 locale 无关）。
- 以后若要加"配置文件里的 `lang`"这一档，插在 `SPC_LANG` 之后、环境链之前（未定）。

## 6. 待定

1. `--json` 的覆盖面与形状（要不要 `schemaVersion`）；
2. 覆盖已有产物 / 密钥的策略（要不要统一一个 `--force`，以及它在 TTY 下要不要问）；
3. 是否需要 `--quiet` / `--verbose`；
4. **`spc`（管理面）是否沿用同一张退出码表** —— 倾向沿用：受众不同，但契约应当一致；
5. 要不要给两个命令加 `--lang` 旗标（现在只有环境变量）。
