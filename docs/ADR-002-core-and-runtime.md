## v2 决策

1. **核心主进程：Node.js（无头）**。负责 auth / RBAC / audit、插件生命周期、宿主 API（唯一边界）、CLI、资源限制、签名验证、**API 扩展注册点**。核心语言选 Node 的理由：单一语言栈（SDK/插件/核心同栈，最低插件门槛）、核心需要提供 node API 能力（驱动插件机制的基础）、DSH/Dokploy 等先例验证可行。
2. **插件运行时：QuickJS 沙箱（默认档）**。**能力插件**（ability）= ESM bundle + manifest，运行于沙箱；沙箱内只有注入的 `@host/api` 模块与白名单纯计算 ESM 依赖。理由见 ADR-005：真沙箱（无 JIT）、微设备友好（~1MB）、ESM-only 静态可审计。
3. **驱动插件（driver，特权档，非沙箱）**：跑在核心侧（或独立 Node 进程），拥有 node API，引驱动（pg/mysql2 等）实现领域能力（db/ssh/docker 客户端），经**API 扩展注册点**注册**权限节点 + API 端点**进 `@host/api`，供沙箱内的能力插件调用；驱动插件内部按面板给的权限列表**自行鉴权**。**核心不内置任何领域 API**。
4. **面板插件（panel）= 默认内置插件，可卸载**：构建 Web 壳 + 组件库，其他插件按统一规范挂载页面；删除面板后无 Web UI，一切管理走 CLI。面板本身也是"组件"——组件库可能很大，属独立分发的资产。
5. **协作插件（hook，设计中）**：钩子触发逻辑，参与核心事件生命周期并干预/修改（notify/arbitrate）；运行位置（核心/沙箱）与默认权限（网络/文件）待 ADR 定稿。
6. **运行时可插拔抽象保留**：`RuntimeBackend` 接口；QuickJS 为默认，子进程档（第三方插件隔离兜底）与未来 Deno 为备选（详见 ADR-005）。
7. **前端**：React。插件前端 bundle 按 manifest 声明的资源路径，由主应用运行时动态加载（import map / 轻量 module federation）。

## 架构图（v2）

```
┌─────────────────────────────────────────────────────┐
│  Node Core（无头，非 root 运行）                       │
│  auth/RBAC/audit · 插件生命周期 · CLI · 资源限制       │
│  基础宿主 API（exec模板/fs/kv/timers）· 权限注册表      │
│  【API 扩展注册点】←─ 驱动插件注册 @host/api/db 等       │
└───────────┬─────────────────────────────────────────┘
            │ 进程内注入 @host/api（QuickJS 沙箱）
┌───────────▼──────────┐   ┌───────────▼──────────────┐
│ QuickJS 沙箱：能力插件 │   │ 驱动插件（特权档，核心侧）  │
│ ESM bundle · 零依赖   │   │ 引 pg/mysql2 等驱动       │
│ 只调 @host/api        │   │ 注册端点并自行鉴权         │
└──────────────────────┘   └──────────────────────────┘
```

## v1 原决策（历史存档，已被 v2 取代）

> v1：Go 无头核心 + Node 插件运行时（每插件独立进程，JSON-RPC over stdio）。
> 被否决理由：Go/Node 双栈增加维护成本；"每插件一个 Node 进程"对微型设备开销大；Go 核心无法直接提供 node API 能力给插件生态。
> v1 中被否决的备选（.so / 嵌入式 WASM / Python / Deno-only）及其理由仍然成立，不再重复。

## 平台策略（v3，2026-08 修订）

- **架构层跨平台**：Node 核心 + QuickJS 沙箱（WASM 版）+ 零环境权力模型**不依赖任何 Linux 专属特性**——Windows 原生支持在原理上成立，**不再需要 agent 模式**（v2 的 agent 决策基于旧架构，已过时）；
- **平台差异点（适配，而非架构差异）**：
  - exec 模板注册表按平台提供：模板声明 `platform` 字段，核心按 OS 加载模板集（nginx/git 在 Windows 上路径/参数不同——最大差异点）；
  - fs 路径收敛需跨平台实现：盘符/长短路径/junction；Windows 符号链接需开发者模式或管理员权限；
  - 资源限制：QuickJS 沙箱自带内存/CPU 限制（跨平台）；进程级配额 Linux 走 systemd/cgroups、Windows 走 Job Object（可后置）；
  - "非 root"底线平移为"非管理员运行"（UAC split token）；
- **发布节奏**：v1 仍 Linux-first（测试面收敛）；Windows 为 v1.x 目标，**架构无阻碍**；
- **微型设备（<256MB）**：QuickJS（~1MB、内存几 MB）天然适配，无需额外档位。

## 后果

- 核心保持最小：只有基础 API + 扩展注册点；领域能力全部由驱动插件承担；
- 插件 = 薄适配器 + ESM bundle，资源占用微设备友好；
- 前端运行时加载仍是必须补齐的架构件。
